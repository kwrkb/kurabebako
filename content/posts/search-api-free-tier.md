## 結論

検索 API は、クエリを渡すと Web の検索結果を JSON で返すサービスです。
AI エージェントに「いまの Web」を調べさせる入口になる 6 つを、「無料枠が毎月戻るか、一回きりか」「カード登録なしで動かせるか」「検索 1 回が何に数えられるか」の 3 点で比べました。

- **カード登録なしで、毎月戻る無料枠で検索結果の抜粋を LLM に渡したい** → Tavily。無料枠が月次で戻り、検索の深さを指定すれば 1 回の消費が決まります
- **Google の検索結果ページを、そのままの構成で JSON にしたい** → SerpApi。同じ検索の繰り返しは枠に数えられません
- **月額プランを持たず、使った分だけ払いたい** → Exa。無料のクレジットが毎月付き、支払い方法の登録も要りません。
  Brave Search API も毎月の無料クレジットを持ちますが、無料の範囲でもカードの登録が要ります。SearchApi と Serper の無料枠は一回きりです

## 比較の前提

- 対象に含めたもの: 公式の料金ページで無料枠の数字を確認でき、REST API にクエリを渡して検索結果を JSON で受け取れる 6 つです。
  Tavily と Exa は AI エージェントからの検索を想定した型、Brave Search API は自前の索引を引く型、SerpApi・SearchApi・Serper は Google などの検索結果ページを構造化して返す型で、返ってくる中身が違います
- 除外したもの: URL を渡してページを取得する API は、検索の機能を持つものも含めて[スクレイピング API 5 つの無料枠比較](/posts/scraping-api-free-tier/)で扱っているため外しました。
  回答の文章を生成して返す機能（Tavily の Research、Brave の Answers など）は、同じ社の中でも検索とは別の単価のため、表には検索の料金だけを載せました
- 検証区分の意味: {{< verified run >}} = AI が実際に動かして確認した / {{< verified spec >}} = 公式ドキュメントで確認したのみ
- 本文の 401・429 は HTTP のステータスコードです。401 はキーが無い・無効なとき、429 はレート制限を超えたときの応答です
- 料金表記の注意: 通貨は各社の料金ページの表記（USD）のままで、税の扱いは Serper だけが「税別」と明記しています。
  数える単位は 3 通りに割れています。クレジット（Tavily・Serper）、検索やリクエストの回数（SerpApi・SearchApi・Brave）、金額（Exa）です。
  棒グラフは「一般の Web 検索を 10 結果まで、要約なしで 1 回」に条件を固定して回数と金額に換算しました。この記事が比べるのは料金と上限で、検索結果の精度や速さの順位は扱いません
- 選び方の軸: 「無料枠」列は、**毎月戻る**（Tavily・SerpApi・Exa・Brave）と**一回きり**（SearchApi・Serper）に分かれます。
  「前提条件」列は、6 つのうち Brave だけが無料の範囲でもカードの登録を求めます。
  「主な制約」列は、検索 1 回の数え方が社ごとに違います。Tavily は検索の深さで消費が変わり、SerpApi はキャッシュされた検索を数えず、Exa は結果の件数で金額が増えます。
  「料金」列は、月額で回数を買う型（Tavily・SerpApi・SearchApi）、前払いでクレジットを買う型（Serper・Brave）、従量だけの型（Exa）の 3 つです
- 検証の手順: Tavily と SerpApi の 2 つに 2026-11-15 に行い、Exa・Brave Search API・SearchApi・Serper は公式ページの確認にとどめています。
  手順は (1) キーなしで呼んだときの応答を記録する (2) API キーを非対話で使い、残りの枠を記録する (3) 同じクエリで検索し、1 回あたりの消費を記録する (4) 残りの枠を再確認する、の 4 つです。
  検索の条件は 10 結果・要約と本文の取得なしに固定し、クエリはこのサイトの分野の英語 1 つだけを使いました。上限に当てる負荷の試験は行っていません
- API キーを AI エージェントに渡す手段は、[シークレット管理 CLI 6 つの比較](/posts/secret-management-cli/)で比べています。
  この記事の検証でも、そこで扱った `op run` で API キーを注入しています

## 各対象の詳細

### Tavily

LLM のエージェント向けに作られた検索 API で、検索結果ごとに本文の抜粋を付けて返します。
6 つのうち、カード登録なしで毎月戻る無料枠を持ち、消費の数え方を API の応答で確かめられた対象です。

{{< fit run >}}
向く: カード登録なしで、毎月戻る無料枠で検索結果の抜粋を LLM に渡したい
向かない: Google の検索結果ページそのものの構成（広告や関連する質問の枠）が欲しい
{{< /fit >}}

- **料金体系**: Project より上の月額プランは、クレジットが増えるほど 1 クレジットの単価が下がります。
  従量（Pay as you go）は、プランの枠を使い切った後に 1 クレジット単位で課金する設定です [1]
- **制約**: `auto_parameters` を有効にすると、検索の深さが自動で `advanced` になることがあり、その場合は 2 クレジットを消費します。
  避けるには `search_depth` に `basic` を明示します [3]。
  残高を返す `/usage` には、検索とは別に 10 分あたり 10 回の上限があります [2]。
  プランやキーの上限を超えたときは 432、従量の上限を超えたときは 433 が返ると docs に書かれています [3]
- **前提条件**: API キーは `Authorization: Bearer` のヘッダーで渡します。レート制限は、同じアカウントのキー全体で共有されます [2][3]
- **検証した内容**: 公式の docs（料金・レート制限・API リファレンス）を確認したうえで、2026-11-15 に無料プランのアカウントで「比較の前提」の 4 手順を実行しました。
  - キーなしの `GET /usage` は 401 で、本文は `{"detail":{"error":"Unauthorized: missing API key."}}` でした
  - `GET /usage` は 200 で、プラン名は `Researcher`、プランの上限は 1,000 でした。キー単位の上限と従量の上限は `null` でした [4]
  - `POST /search` に `include_usage: true` を付けると、応答の `usage.credits` に消費が出ます。`search_depth: basic` は 1、同じクエリの `advanced` は 2 でした。
    結果はどちらも 10 件で、1 件目の抜粋は basic が 158 文字、advanced が 2,314 文字でした
  - `auto_parameters: true` を付けて深さを指定しない検索は 2 クレジットで、応答には自動で選ばれた設定として `"search_depth":"advanced"` が入っていました
  - `/usage` の値は、検索の直後には動きませんでした。約 3 分半後まで 0 のままで、約 11 分後は 3 でした（3 回の応答が返した消費の合計は 5）。
    同じ時点でダッシュボードの使用量は 5 でした。1 回ごとの消費は、`/usage` の差分ではなく応答の `usage.credits` で見るほうが確実です
  - 応答のヘッダーに、レート制限の残りを示す項目はありませんでした

### SerpApi

Google をはじめとする検索エンジンの結果ページを取得し、構造化した JSON で返す API です。
この記事の対象では、同じ検索を繰り返したときに枠が減らないことを実行で確かめた対象です。

{{< fit run >}}
向く: Google の検索結果ページを、そのままの構成で JSON にしたい。同じ検索を繰り返し参照する
向かない: 無料枠でまとまった回数を検索したい（月次の枠が 6 つの中で小さい）
{{< /fit >}}

- **料金体系**: 月の枠を使い切ったときは、早期更新（Automatic Early Renewal）を有効にしておくか手動で更新すると、枠が補充されて更新日が動きます [5]
- **制約**: 結果の件数は消費に影響せず、100 件の応答も 0 件の応答も 1 検索です [5]。
  1 時間あたりの上限は、料金ページでは Free が 50 ですが、アカウントの情報を返す API の `account_rate_limit_per_hour` は 250 でした。
  どちらが実際の上限かは、負荷の試験を行っていないため確かめていません [5][6]
- **前提条件**: API キーは URL のクエリ `api_key` で渡す作りです。URL をログに残すとキーも残ります。
  アカウントの情報を返す API は無料で、月の枠には数えられません。応答にはキーとメールアドレスも含まれます [6]
- **検証した内容**: 公式の料金ページと Account API のページを確認したうえで、2026-11-15 に Free Plan のアカウントで「比較の前提」の 4 手順を実行しました。
  - キーなしの `GET /account.json` は 401 で、本文は `{"error":"Invalid API key. Your API key should be here: https://serpapi.com/manage-api-key"}` でした
  - `GET /account.json` は 200 で、`plan_name` は `Free Plan`、`searches_per_month` は 250 でした
  - `GET /search.json`（`engine=google`）は 200 で、`organic_results` は 9 件でした。既定の 1 ページ目の件数で、10 件ちょうどではありません
  - 同じ検索をもう 1 回送ると、1 回目と同じ `search_metadata.id` と `created_at` の結果が返りました（キャッシュ）。
    2 回の検索の前後で、`this_month_usage` が増えたのは 1 だけでした
  - `this_month_usage` への反映は、検索の約 1 秒後にはまだ無く、数秒後に入りました

### Exa

独自の索引を持つ検索 API で、月額プランを置かず、検索の種類ごとの従量だけで課金します。
無料のクレジットが毎月付き、支払い方法の登録なしで始められます。

{{< fit spec >}}
向く: 月額プランを持たず、使った分だけ払いたい。検索の速さと深さを用途ごとに選びたい
向かない: 1 回の検索で多くの件数を返させたい（件数が増えると金額が加わる）
{{< /fit >}}

- **料金体系**: 検索とは別に、ページの本文の取得と AI による要約にも、ページ数に応じた単価があります [7]
- **制約**: 表の「主な制約」列に載せたとおりです [7]
- **前提条件**: 無料プランでも、MCP サーバーとすべてのエンドポイントが使えると料金ページに書かれています [7]
- **検証した内容**: 公式の料金ページを 2026-11-15 に確認しました。アカウントを作っていないため、実行はしていません

### Brave Search API

Brave が自前で集めた索引を引く検索 API です。料金ページは、Google や Bing の結果に依存しないことを特徴に挙げています。
6 つのうち、無料の範囲でもカードの登録を求めるのはここだけです。

{{< fit spec >}}
向く: Google や Bing に依存しない索引を使いたい。カードの登録は構わない
向かない: カードを登録せずに無料枠だけで試したい
{{< /fit >}}

- **料金体系**: Search とは別に、要約した回答を返す Answers があり、リクエスト数に加えてトークン数でも課金されます [8]
- **制約**: 毎月の無料クレジットは、プランの欄では「USD 5 分」、ページ上部の案内では「最大 USD 20 分」と書かれていて、同じページの中で食い違っています。
  この記事の表と棒グラフは、プランの欄の値で書いています [8]
- **前提条件**: カードを求める理由は、FAQ に「不正利用を防ぐため」とあります。課金されるのは自分で買ったクレジットの分だけ、とも書かれています [8]
- **検証した内容**: 公式のページ（プランと FAQ）を 2026-11-15 に確認しました。カードの登録が要るため、実行はしていません

### SearchApi

Google などの検索結果ページを JSON で返す API で、月額で検索の回数を買う型です。
無料で使えるのは登録時のリクエストだけで、月次で戻る枠は料金ページにありません。

{{< fit spec >}}
向く: Google の検索結果を月額で、まとまった回数取りたい
向かない: 無料枠を毎月使い続けたい
{{< /fit >}}

- **料金体系**: 上位のプランほど、検索 1,000 回あたりの単価が下がります [9]
- **制約**: 表の「主な制約」列に載せたとおりです [9]
- **前提条件**: 登録時のリクエストが一回きりか月次かは、料金ページからは決まりません [9]
- **検証した内容**: 公式の料金ページを 2026-11-15 に確認しました。アカウントを作っていないため、実行はしていません

### Serper

Google の検索結果を返す API で、月額プランを持たず、クレジットを前払いで買う型です。
買う量が多いほど単価が下がり、買ったクレジットには有効期限があります。

{{< fit spec >}}
向く: Google の検索結果を、前払いでまとめて安く買いたい
向かない: 少ない回数を月ごとに払いたい（最小の購入単位が大きい）
{{< /fit >}}

- **料金体系**: 上位の購入単位ほど、クレジットの単価と 1 秒あたりのクエリ数の上限が上がります [10]
- **制約**: 検索の種類やオプションごとに何クレジットを消費するかは、トップページの料金の節には書かれていません [10]
- **前提条件**: 有効期限の記載があるのは有料のクレジットだけです [10]
- **検証した内容**: 公式のトップページ（料金の節と FAQ）を 2026-11-15 に確認しました。アカウントを作っていないため、実行はしていません

## 用途別の選び方

無料枠が毎月戻るか、カードが要るか、返ってくる結果の型の順に絞ると、次のように分かれます。

{{< svg src="search-api-free-tier-flow.svg" alt="用途別の判断フロー。カード登録なしで毎月戻る無料枠で抜粋を LLM に渡したいなら Tavily、Google の検索結果ページをそのまま JSON にしたいなら SerpApi、月額なしの従量だけで払いたいなら Exa、Google や Bing に依存しない索引でカード登録が構わないなら Brave Search API、Google の結果をまとめて買うなら月額の SearchApi か前払いの Serper" >}}

- カード登録なしで、毎月戻る無料枠で検索結果の抜粋を LLM に渡したい → Tavily。決め手は「無料枠」列と「主な制約」列です。
  検索の深さを明示しておくと、1 回の消費が読めます
- Google の検索結果ページを、そのままの構成で JSON にしたい → SerpApi。決め手は「無料枠」列と「主な制約」列です。
  同じ検索を繰り返す用途では、キャッシュが枠を減らしません
- 月額プランを持たず、使った分だけ払いたい → Exa。決め手は「料金」列と「前提条件」列です
- Google や Bing に依存しない索引を使いたく、カードの登録は構わない → Brave Search API。決め手は「無料枠」列と「前提条件」列です
- Google の検索結果をまとまった回数取りたい → 月額なら SearchApi、前払いなら Serper。決め手は「料金」列と「無料枠」列です。
  どちらも無料枠は月次で戻らないので、試し終えたら有料に移るかを決めることになります

検索結果の URL からページの本文を取得する段階は、[スクレイピング API 5 つの無料枠比較](/posts/scraping-api-free-tier/)で比べています。
検索される語そのものの月間検索数を調べる手段は、[キーワード調査ツール 6 つの比較](/posts/keyword-research/)で扱っています。

## よくある質問

### 検索 API は無料で使い続けられますか？

毎月戻る無料枠を持つのは、Tavily（月 1,000 クレジット）・SerpApi（月 250 検索）・Exa（毎月 USD 10 分）・Brave Search API（毎月 USD 5 分）です [1][5][7][8]。
SearchApi の 100 リクエストと Serper の 2,500 クエリには、月次で戻るという記載がありません [9][10]。

### クレジットカードの登録は要りますか？

Tavily・Exa・SearchApi・Serper は、公式のページにカードや支払い方法の登録が要らないと書いています [1][7][9][10]。
Brave Search API は無料の範囲でもカードの登録を求めます [8]。SerpApi の料金ページには、カードの要否の記載がありません [5]。

### Tavily の料金はいくらですか？

無料の Researcher は月 1,000 クレジットで、有料は Project の USD 30/月（4,000 クレジット）からです [1]。
検索 1 回の消費は basic で 1 クレジット、advanced で 2 クレジットなので、同じプランでも検索の深さで検索できる回数が変わります [1]。

### SerpApi の代替になる検索 API はどれですか？

Google の検索結果ページを返す型は、この記事の対象では SearchApi と Serper です [9][10]。
SerpApi の Starter は USD 25/月で 1,000 検索、SearchApi の Developer は USD 40/月で 10,000 検索、Serper の Starter は USD 50 の前払いで 50,000 クレジットです [5][9][10]。
SearchApi と Serper の無料枠は一回きりなので、月次の無料枠で比べると条件が変わります。
